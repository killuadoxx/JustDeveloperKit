# jd — Just Developer Kit

Личный CLI для повседневной работы: система, данные, сеть, файлы, заметки, git,
магазин расширений и темы оформления.
Запускается без сборки: Node 24 сам исполняет `.ts`. Из зависимостей — только
`chalk` (для цвета и неонового оформления), и у него самого зависимостей нет.

```bash
node src/cli.ts            # интерфейс с вкладками разделов
node src/cli.ts list       # все команды
node src/cli.ts help sys   # справка по команде
```

## Интерфейс

`jd` без аргументов открывает полноэкранное меню: рамка, вкладки разделов и
панель деталей по выбранной команде.

```
╭─ jd · Just Developer Kit ─────────────────────────────────────────────── v0.4.0 ─╮
│  📂 demo-app │ Система │ Разработка │ Магазин │ Данные │ Сеть │ Файлы │ Заметки │
├────────────────────────────────────────┬─────────────────────────────────────────┤
│  store                                 │ init                                    │
│❯ preset                                │ команда jd preset                       │
│  theme                                 │                                         │
│  doctor                                │ 📦 Пресеты                              │
│  snip                                  │ Готовые наборы: Telegram-бот, API,       │
│                                        │ Prisma, очереди — в один шаг             │
├────────────────────────────────────────┴─────────────────────────────────────────┤
│  ↑↓ выбор · ←→ разделы · Enter запустить · / поиск · Esc выход · 5 в разделе     │
╰──────────────────────────────────────────────────────────────────────────────────╯
```

Клавиши:

| Клавиша | Что делает |
|---|---|
| `↑` `↓` (или `j` `k`) | Выбор команды в списке |
| `←` `→` (или `h` `l`, `Tab`) | Переключение разделов |
| Набор текста, `/` | Поиск сразу по всем разделам |
| `Enter` | Запустить выбранное |
| `PageUp` / `PageDown`, `Home` / `End` | Быстрое перемещение по длинному списку |
| `Esc` | Очистить поиск, второй раз — выйти |

Рамка подстраивается под размер окна: растёт под содержимое (а не занимает экран
пустотой), ужимается по высоте терминала, а на узком окне (меньше 58 колонок)
прячет панель деталей и оставляет список на всю ширину. Минимум — 45 колонок.

## Требования

Node **>= 22.18** (проверено на 24.13). Нужен `npm install` один раз — ради `chalk`.
Ни TypeScript, ни бандлера, ни сборки: `node:sqlite`, `node:test`, `fetch` и запуск
`.ts` уже внутри Node.

Тесты — на встроенном `node:test`, без единой зависимости:

```bash
npm test        # 71 тест: вёрстка TUI, разбор .me.json, порты, магазин, темы
```

## Как запускать удобно

Из корня проекта:

```powershell
.\jd.cmd sys          # или
node src\cli.ts sys
```

### Глобально как `jd` (npm link)

В `package.json` команда уже прописана в `bin`:

```json
{
  "name": "jd-cli",
  "version": "0.4.0",
  "private": true,
  "type": "module",
  "bin": { "jd": "./src/cli.ts" },
  "engines": { "node": ">=22.18" },
  "dependencies": { "chalk": "^5.6.2" }
}
```

Дальше один раз из корня проекта:

```bash
npm link
```

Появится глобальная команда `jd`, доступная из любой папки. Сборка не нужна:
в `bin` указан `.ts`, а Node 24 исполняет его сам (шебанг `#!/usr/bin/env node`
в `src/cli.ts` уже стоит).

```bash
jd --version          # 0.4.0
jd scan
jd run
```

Отменить: `npm unlink -g jd-cli`. Флаг `private: true` линковке не мешает —
он запрещает только публикацию в npm.

Ещё есть npm-скрипты: `npm run jd`, `npm run menu`, `npm run list`, `npm run help`, `npm test`.

## Новое: порты и git

### `jd scan` — какие дев-порты заняты

По умолчанию проверяется список популярных портов (быстро и читаемо), полный
диапазон — по флагу. Порт «занят», если он либо отвечает на подключение, либо
виден в таблице слушателей (со вторым источником видно PID и имя процесса).

```bash
jd scan                              # популярные: 3000, 5173, 8080, 27017, 6379, …
jd scan --range=3000-9000            # весь диапазон: компактная сетка + таблица занятых
jd scan --ports=3000,5000,8080       # свой набор
jd scan --all                        # показать и свободные, и занятые
```

После сканирования команда спрашивает: «Хотите убить какой-то из занятых портов?» —
и даёт выбрать порт стрелками. После убийства порт перепроверяется, а не считается
освобождённым на слово.

### `jd killport` — освободить один порт

```bash
jd killport                 # спросит номер порта
jd killport 3000            # сразу к делу
jd killport 8080 --dry      # только показать, кто держит, ничего не убивать
jd killport 8080 --yes      # без подтверждения
```

Показывает PID, имя процесса и командную строку, затем проверяет, что порт
действительно освободился.

### `jd push` — новый проект на GitHub за один шаг

```bash
jd push                                                  # спросит ссылку
jd push --url=https://github.com/user/repo.git           # сразу
jd push --url=git@github.com:user/repo.git --yes         # без вопросов
jd push --message="первый коммит" --branch=main
```

Что делает: создаёт `.gitignore` (шаблон под Node/TS, если есть `package.json`),
`git init` с веткой `main`, `git add -A`, `git commit -m "init"`, добавляет
`origin` и делает `git push -u origin main`. Каждый шаг — под своим спиннером.

Команда безопасна для повторного запуска: существующий `.gitignore` не
перезаписывается, уже настроенный `origin` переиспользуется, а если изменений нет —
коммит пропускается. Если не задан `user.email`, она спросит имя и e-mail и
пропишет их **локально** в репозитории.

## Локальный контекст проекта: `.me.json`

Если в папке (или выше по дереву) лежит `.me.json`, `jd` подхватывает его команды
и показывает их **первым блоком** в меню и в `jd list`:

```
📂 Команды проекта [demo-app]
 🚀 Dev Server              npm run dev
 ⚗️ Prisma Push             npx prisma db push
 📦 Build Project           npm run build
```

Нет файла — нет блока, ничего лишнего не показывается. Битый файл не скрывается:
`jd` скажет, что именно не разобралось.

### `jd init` — создать конфиг

```bash
jd init                  # шаблон из трёх команд
jd init --from-package    # собрать команды из scripts в package.json
jd init --force           # перезаписать существующий
jd init --open            # сразу открыть в редакторе
```

Если файл уже есть, команда предупредит `⚠ Файл .me.json уже существует!` и
подскажет, что делать. Шаблон:

```json
{
  "projectName": "Имя вашего проекта",
  "commands": [
    { "name": "🚀 Dev Server", "cmd": "npm run dev" },
    { "name": "⚗️ Prisma Push", "cmd": "npx prisma db push" },
    { "name": "📦 Build Project", "cmd": "npm run build" }
  ]
}
```

### Конфиг — это знание о проекте, а не только список команд

Кроме `name`, `cmd` и `desc` у команды можно указать:

```json
{
  "projectName": "my-app",
  "env": { "NODE_ENV": "development" },
  "ports": [3000, 5173],
  "commands": [
    {
      "name": "🚀 Dev Server",
      "cmd": "npm run dev -- --port {{port}}",
      "cwd": "apps/web",
      "env": { "PORT": "3000" },
      "inputs": [{ "name": "port", "prompt": "Порт", "default": "3000" }]
    },
    {
      "name": "⚗️ Prisma Push",
      "cmd": "npx prisma db push",
      "confirm": true,
      "dependsOn": ["📦 Build Project"]
    }
  ]
}
```

| Поле | Смысл |
|---|---|
| `cwd` | Своя рабочая папка относительно папки проекта |
| `env` | Свои переменные окружения (складываются с `env` проекта) |
| `confirm` | Спросить подтверждение перед запуском — для опасного |
| `dependsOn` | Что выполнить перед этой командой; падение зависимости останавливает цепочку |
| `inputs` | Параметры: в `cmd` пиши `{{имя}}`, значение спросят или возьмут из `--имя=значение` |
| `ports` (у проекта) | Порты проекта — их проверяет `jd scan --project` и `jd doctor` |

Параметры подставляются с экранированием, так что значение с пробелами не сломает
команду. Цепочки `dependsOn` защищены от циклов. `jd init --from-package` сразу
помечает `confirm: true` те скрипты, где встречается `deploy`, `migrate`, `db push`
или `reset` — чтобы не нажать такое случайно.

`--from-package` подбирает эмодзи по имени скрипта (`dev` → 🚀, `build` → 📦,
`test` → 🧪, `prisma`/`migrate` → ⚗️ и так далее), а `desc` заполняет самим телом
скрипта.

### `jd run` — выполнить

```bash
jd run                    # выбрать стрелками
jd run dev                # по имени, с нечётким поиском
jd run 2                  # по номеру из списка
jd run --list             # только показать
jd run build --print      # показать команду, но не запускать
```

Пока команда молчит — висит неоновый спиннер; как только пошёл вывод, спиннер
убирается и вывод идёт живьём. В конце: код возврата и время. Если команда упала,
`jd run` возвращает ненулевой код — можно использовать в скриптах. `Ctrl+C` гасит
всё дерево процессов, а не только `npm`, так что dev-сервер не останется висеть.

`cwd` для команд — папка с `.me.json`, даже если запустить `jd run` из подпапки.

### `jd doctor` — что не так с проектом

```bash
jd doctor
```

Проверяет восемь вещей за один прогон: версию Node против `engines.node` в
`package.json`, `.me.json` (есть ли и разбирается ли), `.env` против `.env.example`
по списку переменных, наличие `node_modules` под объявленные зависимости,
согласованность `package-lock.json` с `package.json`, состояние git, `.gitignore`
(не уедут ли `node_modules` или `.env` в репозиторий) и занятость портов проекта.

```
   ЧТО                   РЕЗУЛЬТАТ
─  ────────────────────  ──────────────────────────────────────────────────
!  Версия Node           v18.20.4 не подходит под ">=22.18"
!  Переменные окружения  в .env не хватает: DATABASE_URL, JWT_SECRET
✓  Зависимости           все 42 на месте в node_modules
✓  Порты                все 2 свободны (.me.json)

  что делать
   → Версия Node: Поставь нужную версию Node (nvm use, fnm use)
   → Переменные окружения: Скорее всего приложение упадёт на старте
```

Если есть ошибки — код возврата ненулевой, так что `jd doctor` можно ставить в
pre-commit или в начало рабочего дня.

## Магазин расширений: `jd store`

Смысл — не вспоминать точные имена пакетов и не лазить каждый раз на npm.
Внутри локальный каталог: **183 пакета** по 15 разделам (веб и API, базы данных,
Telegram и боты, AI и LLM, валидация, логи и мониторинг, CLI и терминал, тесты,
утилиты, очереди и задачи, парсинг и файлы, безопасность, сборка и типы, качество
кода, инфраструктура) — с коротким описанием на русском, ссылкой на npm и признаком
«ставится в devDependencies».

```bash
jd store                                   # обзор: разделы → пакеты → карточка → установка
jd store list                              # весь каталог по разделам
jd store list --category="Telegram и боты"  # только один раздел
jd store search grammy                     # поиск по имени, описанию и тегам
jd store show grammy                       # карточка: что это, как ставить, что уже стоит
jd store install grammy zod --dev           # поставить в текущий проект
jd store installed                          # что уже стоит здесь и что из этого — из каталога
jd store history                            # что и когда ставилось
```

Установка идёт тем менеджером, чей lock-файл лежит рядом (`pnpm-lock.yaml`,
`yarn.lock`, `bun.lockb`, иначе `npm`). Каждый пакет помечается в списке `✔`, если
он уже в `package.json`, и рядом видно его версию. Если `package.json` нет — `jd`
спросит и создаст его. Кнопка «стоп»: `--dry` показывает команду, но ничего не делает.

### Свои пакеты: одна строка вместо формы

Каталог — это стартовая полка. Свои записи добавляются командой установки, как её
написал бы в терминале, плюс описание:

```bash
jd store add "npm install grammyjs"          # интерактивная форма: разберёт команду сам
jd store add "pnpm add -D prisma@6" --desc="Схема и миграции" --category="Базы данных"
```

Из `npm install grammyjs` команда сама достанет имя пакета, версию и признак `dev`,
а если имя похоже на опечатку — предложит правильное (`grammyjs` → `grammy`, и
`@grammyjs/runner` в списке похожих). Описание спрашивается обязательно: без него
запись через месяц ничего не скажет.

Что хранится в записи: имя, спецификация для установки (`prisma@6`), короткое
название, описание, раздел, теги, ссылка и признак `dev`. Дальше:

```bash
jd store edit grammy            # правка: значения по умолчанию — текущие
jd store remove grammyjs        # своя запись удаляется, базовая — скрывается
jd store restore grammyjs       # вернуть скрытую базовую запись
```

Свои записи неприкосновенны: обновление базового каталога в коде их не перезапишет.
Правка базовой записи тоже делает её твоей — каталог её больше не трогает.

## Пресеты: `jd preset`

Пресет — это набор под задачу: пакеты, npm-скрипты, переменные окружения и
файлы-заготовки. Семь встроенных:

| Пресет | Что внутри |
|---|---|
| `telegram-bot` | grammy, zod, pino + готовый `src/bot.ts` с `/start`, `/help`, `/ping` и перехватом ошибок |
| `api-rest` | Fastify, CORS, zod-валидация, `/health` и `/echo`, аккуратное завершение |
| `prisma-sqlite` | Prisma 6, схема с `User` и `Post`, `src/db.ts`, скрипты миграций |
| `cli-tool` | commander, chalk, ora + каркас CLI с двумя командами |
| `scraper` | Playwright, cheerio, `p-limit` + обход ссылок и сбор заголовков |
| `worker-queue` | BullMQ, Redis, воркер с логами, повторами и graceful shutdown |
| `node-lib` | tsup, vitest, строгий tsconfig + первый тест |

```bash
jd preset                        # выбрать стрелками и посмотреть карточку
jd preset list                   # таблица: что внутри и сколько пакетов уже стоит
jd preset show telegram-bot      # карточка + план, если добавить --files
jd preset apply telegram-bot     # применить (покажет план и спросит подтверждение)
jd preset apply api-rest --dry   # только показать план
jd preset apply api-rest --no-install   # скрипты, .env и файлы без установки пакетов
```

Перед применением `jd` показывает план: какие пакеты появятся, какие скрипты
добавятся в `package.json`, какие переменные попадут в `.env` и `.env.example`,
какие файлы будут созданы — и что при этом **пропускается**, потому что уже есть.
Правила простые и жёсткие:

- существующие файлы не перезаписываются никогда (`✔ пропущу`);
- существующие скрипты не затираются;
- значения в `.env` не меняются — дописываются только отсутствующие ключи;
- если создаётся `.env`, а `.gitignore` уже есть, `.env` в него дописывается —
  секреты не уедут в репозиторий;
- в `package.json` добавляется `"type": "module"`, если его там не было (шаблонам
  нужны `import`) — это видно в плане заранее.

Пакеты ставятся первыми: если установка упала, файлы и скрипты не появляются зря.

### Свои пресеты

```bash
jd preset new                    # собрать вручную: разделы каталога, мультивыбор Space, скрипты, переменные
jd preset from-project my-stack  # собрать из текущего проекта: пакеты, скрипты, имена переменных
jd preset export my-stack --out=my-stack.json
jd preset import my-stack.json   # перенести на другую машину или дописать файлы руками
jd preset remove my-stack
jd preset apply my-stack
```

`from-project` берёт `dependencies`, `devDependencies`, все скрипты и **только имена**
переменных из `.env` — значения не копируются никогда. Файлы-заготовки удобнее
дописывать в экспортированном JSON (поле `files`, содержимое в `content`) и
импортировать обратно.

Заготовки встроенных пресетов лежат живыми файлами в `src/templates/<пресет>/…` —
их можно читать и править как обычный код.

## Темы оформления: `jd theme`

Семь палитр: `tokyo` (по умолчанию), `neon`, `matrix`, `sunset`, `nord`, `gruvbox`
и `mono` (почти без цвета). Тема меняет и интерфейс, и неоновый логотип.

```bash
jd theme                 # выбрать с предпросмотром: полоса цветов видна сразу в списке
jd theme list            # таблица тем
jd theme show matrix     # посмотреть образец, не применяя
jd theme set matrix      # применить и запомнить
jd theme reset           # вернуть Tokyo Night
```

Тема запоминается в базе, а на один запуск переопределяется переменной:

```bash
JD_THEME=matrix jd scan
```

## Примеры

```bash
# узнать, что реально приходит от сервиса

node src/cli.ts conv jwt eyJhbGciOi...

# посмотреть, что лежит в ответе API, по-человечески
```

## Где хранятся данные

Всё локальное, в SQLite: `%USERPROFILE%\.jd\jd.db` — сниппеты, заметки, задачи, история
HTTP-запросов, каталог магазина, пресеты и выбранная тема. Переопределяется
переменной `JD_HOME`.

Базовый каталог магазина (183 пакета) засевается в базу лениво, при первом обращении
к `jd store`, и только добавляет отсутствующее: правки и удаления пользователя
не откатываются.

## Как добавить свою команду

Положи файл в `src/commands/` — он подхватится автоматически, попадут в `jd list`
и в меню. Достаточно `export default`:

```ts
import type { Command } from '../core/registry.ts';
import { C, fg, paint } from '../core/theme.ts';

export default {
  name: 'hello',
  aliases: ['hi'],
  group: 'Разное',       // раздел в меню
  title: 'Привет',
  desc: 'Проверка связи',
  usage: 'jd hello [имя]',
  examples: ['jd hello мир'],
  run({ argv }) {
    process.stdout.write(paint(`  привет, ${argv[0] ?? 'мир'}!\n`, fg(C.ok)));
  },
} satisfies Command;
```

Из коробки доступно (см. `src/core/`):

- `neon.ts` — неоновый логотип, градиенты на `chalk`, анимированный спиннер, `runSteps`
- `dashboard.ts` — полноэкранный интерфейс: рамка, вкладки, поиск; отрисовка вынесена
  в чистую `renderFrame()`, поэтому вёрстку можно проверять тестом
- `project.ts` — `.me.json`: поиск вверх по дереву, разбор, параметры, цепочки, `exec`
- `market.ts` — магазин: каталог в базе, разбор `npm install …`, установка, план и
  применение пресета
- `catalog.ts` — базовый каталог пакетов (данные, а не логика)
- `presets.ts` — встроенные пресеты и шаблоны файлов из `src/templates/`
- `themes.ts` — палитры как данные; `applyTheme()` меняет `C` и `N` на месте,
  поэтому ни одна команда о темах не знает
- `ui.ts` — рамки, таблицы, полосы, спарклайны, перерисовка кадра (`Frame`)
- `ports.ts` — кто слушает порт, чей PID, проверка порта подключением, убийство процесса
- `input.ts` — меню с поиском, множественный выбор (Space), ввод строки, подтверждение
- `theme.ts` — палитра и градиенты (уважает `NO_COLOR` / `FORCE_COLOR`)
- `store.ts` — SQLite: `snippets`, `notes`, `todos`, `history`, `kv`, `pkgs`, `presets`, `installs`
- `shell.ts` — запуск процессов, PowerShell с JSON, буфер обмена, открытие ссылок
- `json.ts` — подсветка JSON, доступ по пути, описание структуры
- `args.ts` — разбор флагов

При добавлении темы или пресета достаточно дописать данные: `themes.ts` и
`presets.ts` — это списки, а не код. Новый пресет сразу появится в `jd preset list`,
в подсказках и в `--help`.

## Цвет

Цвет включается сам в терминале и выключается в пайпах. Управление:

- `--no-color` — принудительно без цвета
- `NO_COLOR=1` — без цвета (стандарт)
- `FORCE_COLOR=3` — цвет даже в пайпе (перебивает `NO_COLOR`)
- `JD_THEME=matrix` — тема на один запуск (сильнее сохранённой)

## Тесты

```bash
npm test                    # весь набор
node --test test/market.test.ts   # один файл
```

Семь файлов, 71 тест, ни одной тестовой библиотеки — только `node:test`:

| Файл | Что проверяет |
|---|---|
| `test/geometry.test.ts` | Вёрстку `renderFrame()` на 6 размерах окна: ширина каждой строки, углы, развилки, прокрутка до 40-го элемента, пустой раздел, эмодзи |
| `test/market.test.ts` | Каталог и пресеты целиком (уникальность имён, наличие шаблонов), разбор `npm install …`, план и применение пресета на временных папках, `.env`, `.gitignore` |
| `test/project.test.ts` | Разбор `.me.json`: мусор в командах, BOM, порты, дубликаты, `{{параметры}}`, `dependsOn` |
| `test/ports.test.ts` | `parsePortSpec`, разбор CSV, реальное прощупывание живого и закрытого порта, `mapLimit` |
| `test/themes.test.ts` | Полноту всех палитр и hex-цветов, переключение, откат после превью, `JD_THEME` |
| `test/util.test.ts` | Ширину строк с эмодзи и ANSI, форматы байт и времени, нечёткий поиск, BOM |
| `test/helpers.ts` | Песочница: `JD_HOME` подменяется на временную папку, чтобы тесты не трогали настоящую базу |

Вёрстка TUI проверяется именно тестом, а не глазами: `renderFrame()` — чистая
функция, которая получает размер терминала аргументом. Именно эти тесты уже поймали
две реальные ошибки: рамку, не влезавшую в 10-строчный терминал, и `ensureGitignored`,
затиравший содержимое `.gitignore` вместо дописывания.

## Идеи на будущее

Развитие `.me.json` — самое перспективное направление:

- `timeout` на команду и `watch: true` — перезапускать при изменении файлов
- `jd run --all` — прогнать цепочку (линт → тесты → сборка) одной командой
- `jd hist` — история запусков: что падало, сколько занимало, что запускали чаще всего
- `jd shell` — под-оболочка, где команды проекта доступны как короткие алиасы
- профили запуска: `jd run dev --profile=local` с набором переменных окружения

Отдельно по командам:

- `jd qr`, `jd cron` (разбор и «когда сработает в следующий раз»), `jd diff`,
  `jd hash` файлов, `jd watch <url>`, `jd env` (сравнить `.env` и `.env.example`)
- `jd scan --watch` — следить за портами и сообщать, когда освободится нужный
- `jd docker` — состояние контейнеров и быстрый вход в контейнер по имени
- `--json` для `scan`, `doctor`, `git` — чтобы вывод можно было гнать в вебхук
- индикатор состояния в шапке меню (порты проекта, замечания `jd doctor`)
- магазин: проверка «есть ли версия новее» через `npm outdated` для установленного
