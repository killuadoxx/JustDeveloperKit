# jd — Just Developer Kit

Личный CLI для повседневной работы: система, данные, сеть, файлы, заметки, git.
Запускается без сборки: Node 24 сам исполняет `.ts`. Из зависимостей — только
`chalk` (для цвета и неонового оформления), и у него самого зависимостей нет.

```bash
node src/cli.ts            # интерфейс с вкладками разделов
node src/cli.ts list       # все команды
node src/cli.ts help sys   # справка по команде
```

## Интерфейс

`jd` без аргументов открывает полноэкранное меню: рамка, вкладки разделов и
панель деталей по выбранной команде.

```
╭─ jd · Just Developer Kit ─────────────────────────────────────────────── v0.3.0 ─╮
│  📂 demo-app │ Система │ Разработка │ Данные │ Сеть │ Файлы │ Заметки │ Разное │
├────────────────────────────────────────┬─────────────────────────────────────────┤
│  push                                  │ init                                    │
│❯ init                                  │ команда jd init                         │
│  run                                   │                                         │
│  doctor                                │ 🛠️ Init Project Config                  │
│  snip                                  │ Создаёт .me.json — команды текущего      │
│                                        │ проекта в меню jd                        │
├────────────────────────────────────────┴─────────────────────────────────────────┤
│  ↑↓ выбор · ←→ разделы · Enter запустить · / поиск · Esc выход · 5 в разделе     │
╰──────────────────────────────────────────────────────────────────────────────────╯
```

Клавиши:

| Клавиша | Что делает |
|---|---|
| `↑` `↓` (или `j` `k`) | Выбор команды в списке |
| `←` `→` (или `h` `l`, `Tab`) | Переключение разделов |
| Набор текста, `/` | Поиск сразу по всем разделам |
| `Enter` | Запустить выбранное |
| `PageUp` / `PageDown`, `Home` / `End` | Быстрое перемещение по длинному списку |
| `Esc` | Очистить поиск, второй раз — выйти |

Рамка подстраивается под размер окна: растёт под содержимое (а не занимает экран
пустотой), ужимается по высоте терминала, а на узком окне (меньше 58 колонок)
прячет панель деталей и оставляет список на всю ширину. Минимум — 45 колонок.

## Требования

Node **>= 22.18** (проверено на 24.13). Нужен `npm install` один раз — ради `chalk`.
Ни TypeScript, ни бандлера, ни сборки: `node:sqlite`, `node:test`, `fetch` и запуск
`.ts` уже внутри Node.

## Как запускать удобно

Из корня проекта:

```powershell
.\jd.cmd sys          # или
node src\cli.ts sys
```

### Глобально как `jd` (npm link)

В `package.json` команда уже прописана в `bin`:

```json
{
  "name": "jd-cli",
  "version": "0.3.0",
  "private": true,
  "type": "module",
  "bin": { "jd": "./src/cli.ts" },
  "engines": { "node": ">=22.18" },
  "dependencies": { "chalk": "^5.6.2" }
}
```

Дальше один раз из корня проекта:

```bash
npm link
```

Появится глобальная команда `jd`, доступная из любой папки. Сборка не нужна:
в `bin` указан `.ts`, а Node 24 исполняет его сам (шебанг `#!/usr/bin/env node`
в `src/cli.ts` уже стоит).

```bash
jd --version          # 0.3.0
jd scan
jd run
```

Отменить: `npm unlink -g jd-cli`. Флаг `private: true` линковке не мешает —
он запрещает только публикацию в npm.

Ещё есть npm-скрипты: `npm run jd`, `npm run menu`, `npm run list`, `npm run help`.

## Команды

| Команда | Что делает |
|---|---|
| `jd` / `jd menu` | Интерактивное меню: стрелки + нечёткий поиск |
| `jd sys [-w]` | Живой дашборд: CPU по ядрам, память, диски, сеть, топ процессов |
| `jd scan` | **Scan Local Ports**: прощупывает дев-порты, зелёный/красный, PID и освобождение в один клик |
| `jd killport [порт]` | **Kill Port**: спрашивает номер порта и завершает процесс на нём |
| `jd ports [порт]` | Кто слушает порт; `jd ports kill 3000` — освободить |
| `jd push` | **Git: Fast Init & Push**: `.gitignore`, `init`, `commit`, `push` в `main` |
| `jd init` | **🛠️ Init Project Config**: создаёт `.me.json` — команды проекта в меню |
| `jd run [имя\|номер]` | Запускает команду из `.me.json` текущего проекта |
| `jd doctor` | Проверка окружения: Node, порты, зависимости, конфиги, git |
| `jd snip add/ls/show/copy/edit/rm` | Личная база сниппетов и команд |
| `jd conv b64/url/jwt/ts/hex/hash/uuid/case/slug` | Конвертеры: кодировки, JWT, unixtime, регистры |
| `jd json [файл] [--query=a.b.0]` | JSON: форматирование, запрос по пути, JSONL, `--shape` |
| `jd csv [файл] [--json] [--stats]` | CSV/TSV: таблица, конверт в JSON, статистика по колонкам |
| `jd table` | JSON-массив объектов как таблица (удобно после `jd http --raw`) |
| `jd http <url> [-H] [--data] [--full]` | HTTP-запрос с подсветкой JSON, таймингом и историей |
| `jd http history` | Последние запросы |
| `jd git [status\|log] [--days=7]` | Сводка по всем репозиториям и отчёт о коммитах |
| `jd big [путь] [--top=12]` | Самые тяжёлые файлы и папки |
| `jd tree [путь] [--depth=2]` | Дерево папок с размерами |
| `jd note <текст>` / `jd note ls` | Быстрые заметки |
| `jd todo <текст>` / `jd todo done 2` | Список дел |

Все команды понимают `--help`:

```bash
jd http --help
```

## Новое: порты и git

### `jd scan` — какие дев-порты заняты

По умолчанию проверяется список популярных портов (быстро и читаемо), полный
диапазон — по флагу. Порт «занят», если он либо отвечает на подключение, либо
виден в таблице слушателей (со вторым источником видно PID и имя процесса).

```bash
jd scan                              # популярные: 3000, 5173, 8080, 27017, 6379, …
jd scan --range=3000-9000            # весь диапазон: компактная сетка + таблица занятых
jd scan --ports=3000,5000,8080       # свой набор
jd scan --all                        # показать и свободные, и занятые
```

После сканирования команда спрашивает: «Хотите убить какой-то из занятых портов?» —
и даёт выбрать порт стрелками. После убийства порт перепроверяется, а не считается
освобождённым на слово.

### `jd killport` — освободить один порт

```bash
jd killport                 # спросит номер порта
jd killport 3000            # сразу к делу
jd killport 8080 --dry      # только показать, кто держит, ничего не убивать
jd killport 8080 --yes      # без подтверждения
```

Показывает PID, имя процесса и командную строку, затем проверяет, что порт
действительно освободился.

### `jd push` — новый проект на GitHub за один шаг

```bash
jd push                                                  # спросит ссылку
jd push --url=https://github.com/user/repo.git           # сразу
jd push --url=git@github.com:user/repo.git --yes         # без вопросов
jd push --message="первый коммит" --branch=main
```

Что делает: создаёт `.gitignore` (шаблон под Node/TS, если есть `package.json`),
`git init` с веткой `main`, `git add -A`, `git commit -m "init"`, добавляет
`origin` и делает `git push -u origin main`. Каждый шаг — под своим спиннером.

Команда безопасна для повторного запуска: существующий `.gitignore` не
перезаписывается, уже настроенный `origin` переиспользуется, а если изменений нет —
коммит пропускается. Если не задан `user.email`, она спросит имя и e-mail и
пропишет их **локально** в репозитории.

## Локальный контекст проекта: `.me.json`

Если в папке (или выше по дереву) лежит `.me.json`, `jd` подхватывает его команды
и показывает их **первым блоком** в меню и в `jd list`:

```
📂 Команды проекта [demo-app]
 🚀 Dev Server              npm run dev
 ⚗️ Prisma Push             npx prisma db push
 📦 Build Project           npm run build
```

Нет файла — нет блока, ничего лишнего не показывается. Битый файл не скрывается:
`jd` скажет, что именно не разобралось.

### `jd init` — создать конфиг

```bash
jd init                  # шаблон из трёх команд
jd init --from-package    # собрать команды из scripts в package.json
jd init --force           # перезаписать существующий
jd init --open            # сразу открыть в редакторе
```

Если файл уже есть, команда предупредит `⚠ Файл .me.json уже существует!` и
подскажет, что делать. Шаблон:

```json
{
  "projectName": "Имя вашего проекта",
  "commands": [
    { "name": "🚀 Dev Server", "cmd": "npm run dev" },
    { "name": "⚗️ Prisma Push", "cmd": "npx prisma db push" },
    { "name": "📦 Build Project", "cmd": "npm run build" }
  ]
}
```

### Конфиг — это знание о проекте, а не только список команд

Кроме `name`, `cmd` и `desc` у команды можно указать:

```json
{
  "projectName": "my-app",
  "env": { "NODE_ENV": "development" },
  "ports": [3000, 5173],
  "commands": [
    {
      "name": "🚀 Dev Server",
      "cmd": "npm run dev -- --port {{port}}",
      "cwd": "apps/web",
      "env": { "PORT": "3000" },
      "inputs": [{ "name": "port", "prompt": "Порт", "default": "3000" }]
    },
    {
      "name": "⚗️ Prisma Push",
      "cmd": "npx prisma db push",
      "confirm": true,
      "dependsOn": ["📦 Build Project"]
    }
  ]
}
```

| Поле | Смысл |
|---|---|
| `cwd` | Своя рабочая папка относительно папки проекта |
| `env` | Свои переменные окружения (складываются с `env` проекта) |
| `confirm` | Спросить подтверждение перед запуском — для опасного |
| `dependsOn` | Что выполнить перед этой командой; падение зависимости останавливает цепочку |
| `inputs` | Параметры: в `cmd` пиши `{{имя}}`, значение спросят или возьмут из `--имя=значение` |
| `ports` (у проекта) | Порты проекта — их проверяет `jd scan --project` и `jd doctor` |

Параметры подставляются с экранированием, так что значение с пробелами не сломает
команду. Цепочки `dependsOn` защищены от циклов. `jd init --from-package` сразу
помечает `confirm: true` те скрипты, где встречается `deploy`, `migrate`, `db push`
или `reset` — чтобы не нажать такое случайно.

`--from-package` подбирает эмодзи по имени скрипта (`dev` → 🚀, `build` → 📦,
`test` → 🧪, `prisma`/`migrate` → ⚗️ и так далее), а `desc` заполняет самим телом
скрипта.

### `jd run` — выполнить

```bash
jd run                    # выбрать стрелками
jd run dev                # по имени, с нечётким поиском
jd run 2                  # по номеру из списка
jd run --list             # только показать
jd run build --print      # показать команду, но не запускать
```

Пока команда молчит — висит неоновый спиннер; как только пошёл вывод, спиннер
убирается и вывод идёт живьём. В конце: код возврата и время. Если команда упала,
`jd run` возвращает ненулевой код — можно использовать в скриптах. `Ctrl+C` гасит
всё дерево процессов, а не только `npm`, так что dev-сервер не останется висеть.

`cwd` для команд — папка с `.me.json`, даже если запустить `jd run` из подпапки.

### `jd doctor` — что не так с проектом

```bash
jd doctor
```

Проверяет восемь вещей за один прогон: версию Node против `engines.node` в
`package.json`, `.me.json` (есть ли и разбирается ли), `.env` против `.env.example`
по списку переменных, наличие `node_modules` под объявленные зависимости,
согласованность `package-lock.json` с `package.json`, состояние git, `.gitignore`
(не уедут ли `node_modules` или `.env` в репозиторий) и занятость портов проекта.

```
   ЧТО                   РЕЗУЛЬТАТ
─  ────────────────────  ──────────────────────────────────────────────────
!  Версия Node           v18.20.4 не подходит под ">=22.18"
!  Переменные окружения  в .env не хватает: DATABASE_URL, JWT_SECRET
✓  Зависимости           все 42 на месте в node_modules
✓  Порты                все 2 свободны (.me.json)

  что делать
   → Версия Node: Поставь нужную версию Node (nvm use, fnm use)
   → Переменные окружения: Скорее всего приложение упадёт на старте
```

Если есть ошибки — код возврата ненулевой, так что `jd doctor` можно ставить в
pre-commit или в начало рабочего дня.

## Примеры

```bash
# узнать, что реально приходит от сервиса
node src/cli.ts http https://api.github.com/repos/nodejs/node

# разобрать токен, который «не работает»
node src/cli.ts conv jwt eyJhbGciOi...

# посмотреть, что лежит в ответе API, по-человечески
node src/cli.ts http https://api.example.com/users --raw | node src/cli.ts table

# какой процесс держит 3000 порт
node src/cli.ts ports 3000

# что я делал на этой неделе
node src/cli.ts git log --days=7

# освободить занятый порт, когда «порт уже используется»
node src/cli.ts scan
node src/cli.ts killport 3000

# выложить свежий проект на GitHub
node src/cli.ts push --url=https://github.com/user/repo.git

# посадить команды проекта на горячую клавишу
cd C:\projects\my-app
jd init --from-package
jd run dev
```

## Где хранятся данные

Всё локальное, в SQLite: `%USERPROFILE%\.jd\jd.db` — сниппеты, заметки, задачи, история
HTTP-запросов. Переопределяется переменной `JD_HOME`.

## Как добавить свою команду

Положи файл в `src/commands/` — он подхватится автоматически, попадут в `jd list`
и в меню. Достаточно `export default`:

```ts
import type { Command } from '../core/registry.ts';
import { C, fg, paint } from '../core/theme.ts';

export default {
  name: 'hello',
  aliases: ['hi'],
  group: 'Разное',       // раздел в меню
  title: 'Привет',
  desc: 'Проверка связи',
  usage: 'jd hello [имя]',
  examples: ['jd hello мир'],
  run({ argv }) {
    process.stdout.write(paint(`  привет, ${argv[0] ?? 'мир'}!\n`, fg(C.ok)));
  },
} satisfies Command;
```

Из коробки доступно (см. `src/core/`):

- `neon.ts` — неоновый логотип, градиенты на `chalk`, анимированный спиннер, `runSteps`
- `dashboard.ts` — полноэкранный интерфейс: рамка, вкладки, поиск; отрисовка вынесена
  в чистую `renderFrame()`, поэтому вёрстку можно проверять тестом
- `project.ts` — `.me.json`: поиск вверх по дереву, разбор, параметры, цепочки, `exec`
- `ui.ts` — рамки, таблицы, полосы, спарклайны, перерисовка кадра (`Frame`)
- `ports.ts` — кто слушает порт, чей PID, проверка порта подключением, убийство процесса
- `input.ts` — меню с поиском, ввод строки, подтверждение
- `theme.ts` — палитра и градиенты (уважает `NO_COLOR` / `FORCE_COLOR`)
- `store.ts` — SQLite: `snippets`, `notes`, `todos`, `history`, `kv`
- `shell.ts` — запуск процессов, PowerShell с JSON, буфер обмена, открытие ссылок
- `json.ts` — подсветка JSON, доступ по пути, описание структуры
- `args.ts` — разбор флагов

## Цвет

Цвет включается сам в терминале и выключается в пайпах. Управление:

- `--no-color` — принудительно без цвета
- `NO_COLOR=1` — без цвета (стандарт)
- `FORCE_COLOR=3` — цвет даже в пайпе (перебивает `NO_COLOR`)

## Идеи на будущее

Развитие `.me.json` — самое перспективное направление:

- `timeout` на команду и `watch: true` — перезапускать при изменении файлов
- `jd run --all` — прогнать цепочку (линт → тесты → сборка) одной командой
- `jd hist` — история запусков: что падало, сколько занимало, что запускали чаще всего
- `jd shell` — под-оболочка, где команды проекта доступны как короткие алиасы
- профили запуска: `jd run dev --profile=local` с набором переменных окружения

Отдельно по командам:

- `jd qr`, `jd cron` (разбор и «когда сработает в следующий раз»), `jd diff`,
  `jd hash` файлов, `jd watch <url>`, `jd env` (сравнить `.env` и `.env.example`)
- `jd scan --watch` — следить за портами и сообщать, когда освободится нужный
- `jd docker` — состояние контейнеров и быстрый вход в контейнер по имени
